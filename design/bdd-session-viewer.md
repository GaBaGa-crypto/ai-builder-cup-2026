# BDD：單場次切段驗證頁（2026-10-15，GB10）

> 使用者要求：把 VM20i ds6（標籤 1 混合，44／20／0）調出來，做成 HTML，要有波形圖跟聲音，驗證目前切的狀況。
> 這頁顯示 ds6 的標籤時間區段＝封存再擴大（實驗室一場），記為 prereg 偏離 D2。

## 「目前切的狀況」是什麼（頁面要講清楚）
- 切削事件＝label.csv 每一列的 start／end（第 2 步建庫照抄，沒有自己切）。
- 非切削事件＝相鄰兩列之間、第一列之前、最後一列之後的空隙，長度 ≥ 0.5 秒才成立。
- 對齊：聲音與控制器檔名時間戳相同（名目偏移 0）；第 2 步估的 ds6 偏移 −0.3／0.0 秒、信心 0.48（錨點：主軸轉速）。

## 場景
- **S1**：頁面列出 129 個事件（切削 64＝標籤 0 44＋標籤 1 20；非切削 65），與 main.sqlite／labels.sqlite 一致；每個事件的起訖與表格一致。
- **S2**：s0、s1、s2 三個聲道可切換播放；MP3 長度與原 WAV 相差 < 0.1 秒。
- **S3**：波形依事件上色（標籤 0、標籤 1、非切削三色），可縮放、點波形跳播、點事件列播放該段；播放游標與表格目前列同步。
- **S4**：波形下方畫控制器主軸轉速，作為切段的獨立參照。
- **S5**：波形資料由原始 WAV 計算（每格最小／最大值），不是由 MP3 解碼。

## 積木對照表
| 需要的能力 | 既有積木 | 動作 |

## v2：做成模組，可選任一場次（2026-10-15，使用者要求）
- 限制：69 場、175 音檔轉 MP3 約 1.4 GB，超過 artifact 上限 → 改為 **GB10 本機模組** `proto/scripts/session_viewer_app.py`（只綁 127.0.0.1），直接串流原始 WAV（無損、支援 HTTP Range 跳播）。
- 頁面上方選「機台→場次」，清單顯示每場 n0／n1／n2、長度、備註；上一場／下一場；網址 `#imi_vm20i-9` 可直接開到指定場次。
- **封存**：VF-10 測試場次（`design/prereg-v1.json` 的 vf10_reference_datasets 以外）預設**不送切段與標籤**，只給波形、聲音、主軸轉速；啟動時加 `--unseal-vf10` 才送（使用者自行決定，等同偏離紀錄要再記一筆）。
- **S6**：`/api/sessions` 回 69 場；`/api/session` 對 ds6 回的事件與 v1 靜態頁逐筆相同（起訖、標籤、工況）。
- **S7**：`/audio/<session_id>/<ch>.wav` 只接受資料庫內的場次與 s0/s1/s2，其餘回 404（不能讀任意檔）；Range 請求回 206。
- **S8**：VF-10 測試場次在未加 `--unseal-vf10` 時，回應中沒有任何事件起訖與 label 欄。
- **S9**：靜態匯出（`session_viewer.py`）與模組共用同一個 `build_payload()` 與同一份範本。
- 積木：`build_payload()` 由 v1 `main()` 抽出（第 2 個呼叫者出現＝真接縫）；Range 串流邏輯由測試用 range_server 改寫進模組；`find`、`read_wav_int16`（msm_io.py）複用。

## v3：加入 PDF 的四頻帶 dB／秒圖（2026-10-15，使用者要求）
- 波形下方加四列頻帶圖：0–4k、1–4k、4–10k、10–24k Hz，顏色同 `MSM_四頻帶聲音報告.pdf`；與波形共用時間視窗、播放游標，點擊可跳播；底色依事件（封存場次無事件底色）；跟著目前選的聲道。
- 資料：`figures/band_trends/cache/<session_id>_<ch>.npz`（band_trends.py 已算好的 0.1 秒格均方），payload 送 dB×10 的 int16；快取不存在時現算（`band_trends.band_ms`）。縮放時每像素取能量平均再換 dB。各頻帶縱軸範圍以整場為準（第 1 百分位到最大值），縮放時不跳動。
- **S10**：payload 的頻帶序列由快取還原後，每秒能量平均與 Excel〈每秒趨勢〉同場同聲道的值相差 ≤ 0.05 dB（抽 3 場驗）。
- **S11**：四列與波形同一時間視窗與游標；點頻帶圖跳播。
- **S12**：VF-10 封存場次仍顯示頻帶圖（頻帶音量不是標籤），但沒有事件底色。
- 積木：頻帶快取與 `band_ms`（band_trends.py）複用；頻帶色同 band_pdf.py 的 `BAND_COLOR`（頁面以 CSS token 定義，另加暗色版本）。

## v4：事件表加「冷卻」欄（2026-10-16，使用者要求：記錄與分類用）
- 事件表在「s0 削波比例」後加「冷卻」欄，目前事件卡片同步顯示；值為「濕切／乾切」。
- 資料：main.sqlite `events.coolant`（build_db.py 依場域寫入：實驗室 wet、產線 dry，依據 MSM 論文）；payload 事件多一欄 `cool`。
- **S13**：VM20i、VMX30Ui 每個事件冷卻＝濕切；VF-10 參照場次（ds2、7、12）＝乾切；表頭順序為「… s0 削波比例｜冷卻｜s0 音量 dBFS」。
- **S14**：封存場次仍不送任何事件（冷卻欄不會讓封存場次多出事件）。
- 積木：`events.coolant` 既有欄位複用；只改 `build_payload()` 與範本，靜態匯出與雲端資料包自動帶到（同一函式、同一範本）。
